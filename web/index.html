Hilfe

  

    Browser
    
WebUSB und Web Serial gibt es nur in Chrome, Edge, Opera und anderen Chromium-Browsern am Desktop (nicht Firefox, nicht Safari). Die Seite muss über https:// laufen – auf GitHub Pages ist das so.

  

  

    Linux: Zugriffsrechte
    
Ohne udev-Regel darf nur root auf den Programmer zugreifen. Einmal einrichten, danach den Programmer neu einstecken:

    
sudo tee /etc/udev/rules.d/60-avr-programmers.rules <<'EOF'
SUBSYSTEM=="usb", ATTR{idVendor}=="16c0", ATTR{idProduct}=="05dc", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="03eb", ATTR{idProduct}=="c7b4", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="1781", ATTR{idProduct}=="0c9f", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="03eb", ATTR{idProduct}=="2104", TAG+="uaccess"
EOF
sudo udevadm control --reload-rules

    
Serielle Programmer (STK500v2, Arduino) brauchen die Gruppe dialout: sudo usermod -aG dialout $USER, danach neu anmelden.

  

  

    Windows: Treiber
    
WebUSB braucht den WinUSB-Treiber. Mit Zadig: Programmer einstecken, Options → List All Devices, Gerät wählen, WinUSB → Install/Replace Driver. Falls avrdude danach meckert, mit Zadig wieder auf libusbK/libusb-win32 umstellen. Serielle Programmer brauchen keinen Extra-Treiber.

  

  

    Es klappt nicht
    
    
      
  • Kein Gerät im Auswahldialog: USB-ID prüfen (lsusb), „alle USB-Geräte anzeigen“ probieren, unter Linux die udev-Regel, unter Windows WinUSB.
    • 
      
  • „Chip antwortet nicht“: Verkabelung (MISO/MOSI/SCK/RESET), Stromversorgung, ISP-Takt langsamer.
    • 
      
  • Falsche Signatur: kein ATtiny13/13A, Wackelkontakt oder Chip defekt.
    • 
      
  • Diamex ISP-Prog-NG: meldet er sich nicht als USBasp, läuft er vermutlich im STK500-Modus → „STK500v2 seriell“ wählen.
    • 
      
  • Geht alles nicht: in Schritt 2 die .hex speichern und am PC mit avrdude flashen – die Einstellungen stecken in der Datei.
